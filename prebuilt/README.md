# prebuilt/

Сюда кладётся **уже собранный и подписанный** `Grimhold3D.apk`, когда релиз режется
через CI, а APK собран локально.

Зачем это нужно: раннер собирает APK не той цепочкой, что `build_apk.sh` — там `javac`,
здесь `ecj`, плюс свои версии `aapt2` и `d8`. Байт-в-байт сборки не совпадают, а в
`version.json` записана sha256 именно локальной сборки, и игра сверяет её после загрузки.
Поэтому опубликовать надо тот же файл, по которому считался `version.json`.

Порядок:

```bash
python3 tools/release.py 1.9 --notes "Что изменилось"
cp dist/Grimhold3D.apk prebuilt/Grimhold3D.apk
git add -A && git commit -m "v1.9" && git push
# запустить workflow release с полем tag = v1.9
```

`release.yml` возьмёт файл отсюда вместо сборки на раннере и всё равно сверит sha256
с `version.json` — не сойдётся, APK к релизу не приложится и сборка упадёт.

**После публикации релиза файл отсюда убирай.** Каждый оставленный APK — это 1.6 МБ
в истории репозитория навсегда, и вдобавок следующий релиз попробует опубликовать
старую сборку (сверка sha256 это поймает, но сборка упадёт на ровном месте).

Если секреты подписи заведены (`KEYSTORE_B64`, `KEYSTORE_PASS`, `KEY_ALIAS`) и папка
пуста, раннер соберёт APK сам.
