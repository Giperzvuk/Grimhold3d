# Обмен художественными ассетами

Здесь живут задания на графику и приёмка. Само ТЗ — в [`CODEX_ART_BRIEF.md`](../CODEX_ART_BRIEF.md)
в корне репозитория, оно остаётся источником истины по стилю, палитре и списку файлов.

```
art/
  README.md            этот файл — как устроен обмен
  check_tiles.py       проверка тайлов поверхностей, запускать до сдачи
  tasks/               задания: одно задание — один файл
  incoming/            сюда кладётся сдача
```

## Как сдавать работу

**Основной путь — в репозиторий.** Ветка на партию, файлы под своим путём:

```bash
git checkout -b art/party1 main
mkdir -p art/incoming/party1
# сюда: tiles/, assets.json, NOTES.md — структура из §D.1 брифа
git add art/incoming/party1 && git commit -m "art: партия 1, поверхности"
git push -u origin art/party1
```

Ветку в `main` не вливаем: исходники идут в максимальном разрешении, 21 тайл по 2–3 МБ — это
около 60 МБ на одну партию, и в истории `main` им не место. В `main` попадут только
уменьшенные до игрового размера ассеты, их соберёт загрузчик. Ветка сдачи живёт, пока
партию не приняли.

**Запасной путь — zip.** Если с гитом не сложилось, архив с той же структурой внутри:

```
grimhold-art/
  tiles/*.png
  assets.json
  NOTES.md
```

Архив целиком, не отдельными файлами и не ссылками на просмотр: разрозненные файлы
теряют структуру, а по ссылке на превью проверку не прогнать.

## Обязательно перед сдачей

Прогнать проверку и **вложить её вывод в `NOTES.md`**:

```bash
python3 art/check_tiles.py art/incoming/party1
```

Скрипт считает то, что на глаз не видно: зеркальную симметрию, ширину общей кромки,
запечённый направленный свет, рамку по краю кадра, расхождение яркости между вариантами,
сохранность детали после уменьшения с NEAREST. Выход `0` — можно сдавать, `1` — нельзя.

Сдача с непройденной проверкой возвращается без разбора. Если считаешь, что порог
неверен для конкретной поверхности — так и напиши в `NOTES.md`, с обоснованием;
это нормальный повод обсудить порог, а не причина промолчать.

Нужен `pillow` и `numpy`:

```bash
pip install pillow numpy
```

## Что происходит после сдачи

1. Прогоняется та же проверка плюс визуальный разбор.
2. Тайлы кладутся в игру и смотрятся при настоящем свете и цветокоррекции локаций —
   крипта уходит в сине-зелёный, шахта в янтарный, лес обесцвечен (§A.4).
3. Результат — в комментарии к issue задания: принято, или что переделать и почему,
   с числами из проверки.

## Почему проверка такая придирчивая

Движок обходится с текстурой жёстко (§A.4): уменьшение фильтрацией NEAREST без сглаживания,
постеризация до 24 уровней на канал, дизеринг 2×2, виньетка, умножение на динамический свет
до 12 источников. Красивый файл на 2048 после этого может рассыпаться. Поэтому приёмка идёт
не по исходнику, а по тому, что видит игрок.
